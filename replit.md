# Sage Oak App Dashboard

Internal analytics + rostering operations dashboard for Sage Oak Charter Schools: Clever usage-CSV analytics with history accumulation, and a per-term application Rostering Status Board with upvotes and issue reporting.

## Run & Operate

- `pnpm --filter @workspace/api-server run dev` — run the API server
- `pnpm --filter @workspace/sage-oak-dashboard run dev` — run the web app
- `pnpm run typecheck` — full typecheck across all packages
- `pnpm --filter @workspace/api-spec run codegen` — regenerate API hooks and Zod schemas from the OpenAPI spec
- `pnpm --filter @workspace/db run push` — push DB schema changes (dev only)
- Required env: `DATABASE_URL`; production also needs `SESSION_SECRET`, `ADMIN_EMAIL`, `ADMIN_PASSWORD`
- Dev admin login: `admin@sageoak.org` / `sageoak-admin`
- Post-publish checks: `pnpm --filter @workspace/scripts run prod-login-check -- <url>` (login/session) and `pnpm --filter @workspace/scripts run sse-stream-check -- <url>` (live-badge SSE stream through the production proxy; needs SMOKE_EMAIL/SMOKE_PASSWORD admin creds; SSE_TRIGGER=0 for a read-only run)

## Stack

- pnpm workspaces, Node.js 24, TypeScript 5.9
- API: Express 5; sessions via express-session + connect-pg-simple; bcryptjs passwords
- Web: React + Vite, amCharts 5 (mandated — no Recharts/Chart.js), TanStack Query hooks generated by Orval
- DB: PostgreSQL + Drizzle ORM
- Validation: Zod (`zod/v4`), `drizzle-zod`

## Where things live

- `lib/api-spec/openapi.yaml` — API contract (source of truth; run codegen after edits)
- `lib/db/src/schema/` — Drizzle schema: `users`, `terms`, `rostering` (applications, app_term_status, upvotes, issues), `usage` (11 tables + import_log)
- `artifacts/api-server/src/lib/auth.ts` — sessions, requireAuth/requireAdmin, startup seeding (admin, 4 terms, session table)
- `artifacts/api-server/src/lib/importer.ts` — CSV classification + upsert import pipeline
- `artifacts/api-server/src/routes/` — auth, users, terms, rostering, feedback, usage, uploads
- `artifacts/sage-oak-dashboard/` — React web app

## Architecture decisions

- CSV upload is JSON (`{files:[{name,content}]}`), not multipart — simpler codegen and works everywhere.
- Daily usage tables upsert by date; snapshot tables upsert by snapshot (export) date; old dates are never deleted (history accumulation requirement).
- New apps in uploads auto-seed rostering rows for the current term with `not_started` statuses.
- Session table is created explicitly at startup — connect-pg-simple's `createTableIfMissing` reads a .sql file from disk and breaks in the esbuild bundle.
- Local email/password auth only (task requirement); no Clerk/Replit auth. No frame-blocking headers so the app is iframe-embeddable.
- Target deploy platform is Railway (`PORT`/`DATABASE_URL` envs); see README for steps.

## Product

- Overview: KPI cards, daily active users line chart, top apps bar chart, device/browser/login-method donuts, per-school table, app engagement table.
- Rostering: per-term status board (student/staff sharing statuses, sync method, owner, notes), upvotes, issue reporting; admin inline editing, term management, copy-statuses-between-terms.
- Issues: open/resolved list, admin resolve/reopen.
- Upload (admin): 12 Clever CSVs, import result + warnings, import log.
- Users (admin): manage staff/admin accounts.

## Gotchas

- `ExportProperties.csv` is required in every upload batch (provides `Export_date`).
- After editing `lib/api-spec/openapi.yaml`, run codegen before touching frontend hooks.
- amCharts 5 Roots must be disposed on unmount.
- The Rostering live badge uses SSE (`GET /api/rostering/events`, heartbeat every 25s, `X-Accel-Buffering: no`, no compression middleware). If a production proxy still buffers/kills the stream, the badge silently degrades to 60s polling + refetch-on-focus — it never breaks. Activity events are in-process, so on multi-instance autoscale a change on another instance reaches clients via the polling fallback.
